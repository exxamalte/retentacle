Single sign-on (OpenID Connect)

Let users sign in through your identity provider. Accounts are matched by email address.

The provider is discovered automatically from the issuer URL. A Sign in with … button appears on the login page once the connection is configured.

Shown on the login button, for example "Sign in with Keycloak".

Base URL of the provider. Its well-known OpenID configuration is used to find all endpoints.

Stored unencrypted in the settings database; keep that file protected.

Must include "openid email" so users can be identified. Add your provider's picture scope as well if needed (e.g. Keycloak requires "microprofile" to send a profile picture).

The exact redirect URI registered with your provider. Leave empty to derive it from the current request — useful when running behind a reverse proxy with a different scheme or host.

People who sign in via the provider without a matching account get a read-only account automatically. Promote them in the Users section below.

Only OIDC can sign in then. The provider connection is verified before this takes effect, so you cannot lock yourself out through an unreachable issuer.
